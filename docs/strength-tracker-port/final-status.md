## Summary

**PARITY: 40 | DEGRADED: 11 | MISSING: 5**

The port preserves the analytic core (all 11 charts, all 3 hero cards, CRUD, achievements, deload signal, sparkline grid, body-weight panel) and gains a cleaner server-driven architecture. The gaps are concentrated in three areas: (1) page-level controls that were deliberately dropped (Demo button, Reset button, set-editor confirm flow, mobile-specific layout branch); (2) Body Weight view degraded from a full sub-page with dedicated hero cards, edit-form parity and a History table into a compact summary-cards + chart + entry-form panel; (3) several small affordances on the workouts table and form (expandable set rows, latest-set pre-fill on initial mount, Δ vs last preview in the weight form).

## Degraded Items (Drill-Down)

### 1. LocalStorage persistence shrunk to URL state

**File:** `apps/dashboard/src/routes/strength-tracker.tsx:50-58`

`SearchSchema` carries `window`, `from`, `to`, `tab`, `exercises`. Defaults are baked into the schema (`window: 'all'`, `tab: 'charts'`, `exercises: 'bench_press,deadlift,squat,pull_ups'`). Only the window preset is mirrored to localStorage (via `WindowSelector`'s effect at `window-selector.tsx:81-83`).

**Effect:** open a fresh tab with no search params → defaults render even if your last session ended on `tab=scan&exercises=bench_press`. Old behaviour: every dropdown/tab/filter selection was sticky across reloads.

**Drop in detail:**

- `st-exercises` → URL only (not seeded from LS)
- `st-view` → URL only
- `st-custom-range` → URL only
- `st-record-filter` → component-local `useState`
- `st-demo-data` → removed (no Demo button)
- `strength-tracker-form` (form draft) → removed
- `st-date-preset` → URL + LS (retained)

`index.ts` still exports `EXERCISES_STORAGE_KEY` and `VIEW_STORAGE_KEY` (constants.ts:60-61) but they are unused.

**Fix path (if desired):** read URL search params at route mount; if any are absent, fall back to localStorage; write through on every navigate. Same pattern as `WindowSelector` but applied to `tab` + `exercises`.

### 2. Demo button missing

**File (old):** `index.tsx:223-228` + `demo-data.ts` (4 KB)

The old page had a "Demo" toggle that loaded 180 days of synthetic workouts (4-day-a-week training, deload at session 18, jittered weights). It was useful for screenshotting/onboarding without prod data.

**New:** no button, no fixture generator. The page-level empty state covers the "no data" case but there's no way to inspect a populated state without real data.

**Fix path:** port `demo-data.ts` if the use case still matters. Otherwise document the removal.

### 3. Reset button missing

**File (old):** `index.tsx:220` + `use-local-state.ts:34-37`

Old's Reset button called `resetConfig()` which removed 7 localStorage keys and reloaded the page. In the new URL-driven world, navigating to `/strength-tracker` with no search params already produces a reset state — but only if you remember the URL. There is no UI affordance.

**Fix path:** add a small "Reset" button to the filter row that navigates to `{to: '/strength-tracker', search: {}}` and clears the one localStorage key (`argo:strength-tracker:window`).

### 4. SetEditor `showConfirm` flow dropped

**Files:** `argo-old/.../set-editor.tsx:33-124` (showConfirm path) vs `argo/.../set-editor.tsx:41-71` (always editable)

Old's WorkoutForm passed `showConfirm` to require the user to tick a checkmark on each set before submission, plus a confirm-modal for add/remove/cycle, plus a final review modal. New skips all of that — the SetEditor is always immediately mutable, and Save commits without a review step.

**Trade-off:** the new flow is faster (1 click less) but loses the "double-check before commit" safety. The preview Badge (`previewParts.join(' · ')`) at `workout-form.tsx:170-176` partially compensates by surfacing aggregates before save.

This is intentional per the brief.

### 5. Workout form draft persistence removed

**File (old):** `workout-form.tsx:11-29` (`FORM_STORAGE_KEY` + `loadStoredForm`) + `:48-51` (useEffect to write).

Old persisted `{exercise, date, sets}` to localStorage on every edit; reloading restored the in-progress draft. New does not.

**Effect:** mid-entry tab close = lost work. Mitigated somewhat by the fact that latest-session sets pre-fill on exercise change, but a custom set list (different weights/reps/types) is lost.

### 6. Latest-set pre-fill on initial mount

**File (old):** `workout-form.tsx:87-93` runs `loadLatestSets(exercise)` exactly once after workouts have loaded if no stored form exists.

**File (new):** `workout-form.tsx:100-105` runs `setSets(previousSets)` whenever `exercise` changes, including after `recentResult` lands (since `previousSets` is derived from it).

Effectively the new code does pre-fill, but it relies on the `useEffect([exercise])` firing again once data resolves (because `previousSets` becomes defined). In practice it works — the initial `[60kg × 5]` default is replaced as soon as the query lands. The eslint-disable on line 104 (`exhaustive-deps`) signals this is fragile if the dependency rules change.

### 7. Body-weight view: Goal card + ETA removed

**File (old):** `body-weight-view.tsx:214-267` — third hero card "Goal" with caption `${dist} · ${formatEta(goalDays)} at current pace`.

**File (new):** `body-weight-panel.tsx:55-160` — 6 metric cards (Current / 7d avg / 30d avg / Weekly Δ / Monthly Δ / kg/week). Goal weight is rendered only as a reference line in the chart (via `userProfileQuery` in `body-weight-chart.tsx:43-46`).

**Effect:** users can no longer see at a glance "X kg to 75 kg · 6w at current pace". The information density of the new cards is higher (6 vs 3) but the projection narrative is gone. `projectGoalDays()` from old's analytics is not ported.

### 8. Body-weight form: Δ preview, duplicate warning, future-date guard

**File (old):** `body-weight-view.tsx:564-673` (WeightForm).
**File (new):** `body-weight-panel.tsx:162-211` (WeightEntryForm).
