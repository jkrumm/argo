# Argo overview

What Argo is and which surfaces it serves. Moved verbatim from the root AGENTS.md (hygiene split); the root keeps the summary and the rules every task needs.

## What Argo Is

Personal dashboard + agent-backbone API for Johannes Krumm, running natively on the Mac mini at
`https://argo.jkrumm.com` (tailnet only). Health/training core: **Garmin Health** (HRV, resting HR, sleep,
stress, daily metrics, recovery score) and **Strength Tracker** (workouts, sets, e1RM, volume,
ACWR, PR detection, body weight) — Argo pulls health data every 6 hours straight from the official Garmin Connect Personal API (a personal API key, `GARMIN_API_KEY`), strength
data is logged manually. Alongside them: a general
an in-process `aiComplete` (`lib/ai-complete.ts`, no HTTP route; backs classification and the astro/marine verdict sentences),
**Usage Tracking** (Claude Code and gateway spend, read from the `usage` schema in the shared database: `usage-tracker` and `agw` write it directly, Argo has no ingest endpoint and reads `usage.records_unique` through the projection `src/lib/usage-source.ts`; each record carries the Claude `account` — `iu`/`me`/`me2`, null off Max billing — filterable on every `/usage` endpoint and a breakdown/groupBy dimension; IU API rows also carry the IU key `iu_key` — `personal`/`athena-team`, each with its own $500 cap, `iuKey` filter and `iu_key` dimension on the records endpoints, `?iuKey` on `iu-budget`/`iu-reconcile`; the **payer** — `iu-sub` (Ultra)/`me-sub`/`me2-sub`, the API credit those subscriptions grant `iu-credit`/`me-credit`/`me2-credit` (billing `api_credit` + account, written by the inference gateway), `iu-api`/`iu-team-api`/`me-api`/`unknown`, derived from billing + account + iu_key in the query layer — is the usage page's default split and filter); also Claude account quota samples (`GET /usage/quota`, `GET /usage/quota-latest`, from `usage.quota_samples`) and picker decisions (`GET /usage/account-picks/summary`, from `usage.account_picks`), IU's portal cost report (`usage.iu_portal_cost`, read by `GET /usage/{iu-budget,iu-reconcile}`) plus the `flow` and `movers` aggregates (`docs/api/usage-iu-portal.md`, `docs/api/usage-pace.md`), shown on the usage page (two tabs, spec `docs/design/usage-tracking.md` v7: **Quotas** (default, `?view=flow`) — a verdict sentence (credit, subscriptions, IU clause) and four cards in one chart form: Claude subscriptions (Combined, the pool weighted by capacity units iu 2 / me 1 / me2 1, recorded and projected, or Accounts, one line each: `?subsView`), Claude API credit (the three pools summed in dollars with the even pace, projection and labelled renewals), the IU personal key and the Athena team key (each a rolling 30 d $500 cap in dollars, recorded from the true rolling sum, projected 30 d as each past day comes back); below them a closed "Routing and demand" disclosure (Router and Demand columns, the selected node's detail via `?node=router|demand:<workflow>`, Athena's spend by producer; follows Range, mounts on open, `?node=` opens it); the Athena team key stays out of every total; **Explore** — the analysis blocks across every payer at once with a Payer multi-select (over time, projects / tools rows, rhythm, weekly volume). The v6 tabs Overview, Claude Max, IU API and Credits are deleted; their `?view=` values still open Quotas. Range (default 7 d) drives only the Routing and demand disclosure, the verdict and the cards are state; data from `GET /usage/{pace,router,demand}`, `/usage/split?by=lane`, `/usage/quota-latest`, `/usage/iu-budget`; `GET /usage/credits/*` is gone, `pace` and `router` replaced it), **Reading**
(Hardcover sync + reading stats), **M365 Explorer** (browse IU Teams chats/channels), **GitLab**
and **Atlassian** surfaces, **WalkingPad**.

**Astro Window** answers "is tonight (or this week) worth going out for?" for Milky Way nightscapes. It is scored by a deterministic engine (`apps/api/src/lib/window-score.ts` — hard gates that name _why_ a night is out, plus weighted 0–1 factors) instantiated per domain (`astro-score.ts`). **The model never computes a number**: the ephemeris, the thresholds and the score are all deterministic, and `aiComplete()` only writes one sentence about an already-finished verdict — see `docs/ASTRO-WINDOW.md`.

The **marine** half of that feature exists **API-only**: `/marine/window` and `/marine/spots` run over the same engine (`marine-score.ts`, `marine-spots.ts`, `clients/marine-upstreams.ts`) and are tested, but the dashboard page was removed on 2026-08-18 — the surf face gets rebuilt deliberately, step by step, on top of the shipped endpoints.

The API doubles as an AI-agent endpoint. Discovery is anchored at three URLs: `GET /` returns a small JSON pointing at the docs and listing the tag groups, `GET /openapi` serves the Scalar interactive UI, and `GET /openapi/json` exposes the raw spec. The OpenAPI contract (paths, tag taxonomy, description quality) is the agent interface — see `apps/api/.claude/rules/openapi.md`. All routes require a bearer except the health probe (see Verify & Monitor).

## Finance vault

Argo is the frontend of Johannes's encrypted finance vault (repo `~/SourceRoot/finances`; `docs/service.md` there is the contract). The vault stays encrypted on the mini; `fin serve` (loopback `127.0.0.1:${FIN_SERVICE_PORT:-4581}`) holds the key only in memory while unlocked. The API relays `/finance/*` to it (`apps/api/src/routes/finance.ts`, secret `FIN_SERVICE_TOKEN`, service status codes passed through, 503 when it is down; see `docs/api/finance.md`). The dashboard's **Finance** section (`/finance/…`, `apps/dashboard/src/features/finance/`) shows one unlock screen while locked (a login form so 1Password fills the vault key), and when unlocked the seven pages — This month, Spending, Recurring, Transactions, Net worth, Depot chart, Tax — with a page-bar sync control (last sync, "syncing…", **Sync now**) and **Lock**; the status is polled every 30 s only while a finance page is open, and a 423 from any data call drops back to the unlock screen. The response types are a pinned copy of the finances repo's `src/api/types.ts` (`features/finance/api/types.ts`, source commit in its header); the pages also curate the books (category, tax tag, recurring override, merchant rule: the four typed curation writes the relay allows, whose request shapes are kept by hand in `api/write-types.ts`; the Depot chart adds hand-kept orders, a drawing document per instrument and the watchlist writes of the market store: lists, entries and the index an ETF tracks): re-copy the pinned file when it changes. Agents never unlock the vault or handle its key; `POST /finance/unlock` is human-only.

## Retired surfaces

Warden was switched off 2026-10-27 and its API is gone; the `warden_snapshots` and `warden_actions` tables are left in the `argo` schema, unused, pending a cleanup migration.

The factory's own pages (needs-you, flow, chain, improve) live in the Console, not in Argo; the Today page links to it (`apps/dashboard/src/lib/console-url.ts` joins a path onto `VITE_CONSOLE_URL`, the Console's own door origin: `make deploy` bakes it from the mini-local one-line file `~/.argo/console-url`, `apps/dashboard/.env.development` points dev at the `.test` door; unset, there is no link). Argo's `/agents/*` API and the Agents and Agent performance pages are gone; the `agent_overview_snapshots`, `agent_narratives` and `agent_review_stats_snapshots` tables stay in the `argo` schema, unused, pending a cleanup migration.
