# API integrations: Reading and Garmin

Moved from `apps/api/AGENTS.md`. Read before changing `/reading/*` (Hardcover, homelab link) or the Garmin Connect client.

## Reading (Hardcover + homelab link)

Argo reaches out to the homelab over SSH; nothing on the homelab calls Argo (the tailnet ACL forbids it). Two env-configured commands, each an argv split on whitespace (no shell, no quoting; `clients/command.ts`), empty = off. Argo never names the source system behind them.

- `READING_STATS_SOURCE_CMD`: stdout is exactly the `POST /reading/stats` body (`{"stats":[...]}`, `{"stats":[]}` when nothing; errors on stderr, non-zero exit). Validated with `StatInputSchema` (0..1000 rows) and upserted through `upsertReadingStats`, the same function the route uses. Pulled when `GET /reading` is served (at most once per 5 min, concurrent requests share one run, 8 s timeout; a failure logs a warning and the page is served from the DB) and at the start of `runHardcoverSync`.
- `READING_SHELF_SINK_CMD`: receives the `GET /reading` JSON (`buildReadingShelf()`) on stdin. Pushed after `runHardcoverSync` (cron and `POST /reading/sync`) and after a page-open pull that ran. Fire-and-forget, 20 s timeout, failures logged; one push at a time, requests during a push coalesce into one trailing push. A command's stdout is capped at 5 MB (child killed).
- `GET /reading` pulls whenever `READING_STATS_SOURCE_CMD` is set, so evidence / design-shot / fixture runs must leave it empty (the default; only the production plist sets it). The sync and the page-open pull share one in-flight run.
- Code: `lib/reading-store.ts` (DB + wiring), `lib/reading-link.ts` (pure: schema, pulled-body validation, throttle). Tests: `clients/command.test.ts`, `lib/reading-link.test.ts`. Production values live in `deploy/com.jkrumm.argo.plist.template`.

## Garmin (Connect Personal API)

`cron/garmin-sync.ts` (every 6 h + a 60 s manual-refresh poll) pulls straight from the official Garmin Connect Personal API through `clients/garmin.ts`; pure DTO → row mapping lives in `lib/garmin-mapping.ts`. Auth is a personal API key (`GARMIN_API_KEY`, `op://vps/argo/GARMIN_API_KEY`) exchanged for a 24 h JWT that the client caches in memory and re-mints when under 1 h is left (and once on a 401). Requests are sequential — rate limits are unpublished. The cron stays disabled while `GARMIN_API_KEY` is empty.

- **Key rotation.** The key expires at most yearly; Garmin emails a week before. Rotate it in 1Password (`op://vps/argo/GARMIN_API_KEY`), then reseal the mini's secrets cache (`make secrets-seed` on the MacBook, or `ask-human.sh` from the mini) and restart the agent with `make deploy`.
- **Typed SDK.** `src/generated/garmin/` is generated by `@hey-api/openapi-ts` (pinned in `package.json`) from the vendored official spec `specs/garmin-personal-api.openapi.json`: `bun run --cwd apps/api gen:garmin`. The token endpoint is not in the spec; the client calls it directly.
- **No daily `vo2_max`.** The Personal API has no daily max-metrics endpoint, so `daily_metrics.vo2_max` is no longer refreshed (existing values are preserved); activities still carry `vO2MaxValue`.
- Tests: `src/lib/garmin-mapping.test.ts`, `src/lib/garmin-client.test.ts` (both in the CI unit set).
