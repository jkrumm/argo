# API usage: quota, picker decisions, models relay

Moved from `apps/api/AGENTS.md`. Read before changing `/usage/quota*`, `/usage/account-picks/*` or `/models/*`.

## Usage quota + picker decisions

Every usage query reads `FROM ${USAGE_ROWS}` (`src/lib/usage-source.ts`): `usage.records_unique` projected onto the column names below (`model_norm`, `project`, `sub_tool` = usage-tracker's canonical `tool` column from migration 0021 (`review`, `lead`, `worker`, `reviewer`, `deep`, a subagent type, `research`, `teamchat`, `agw`, …; no `:` step suffix), `billing`, `iu_key`, …); Argo never writes the `usage` schema. The legacy `argo.usage_record`/`quota_sample`/`account_pick`/`iu_portal_*` tables are gone (migration `0032`).

**Payer** (`src/lib/usage-query.ts` `PAYER_SQL`, no column, works on all history): `billing=max ∧ account=iu` → `iu-sub` (the IU subscription is Ultra, $200), `max ∧ me` → `me-sub`, `max ∧ me2` → `me2-sub` (third Max subscription, onboarded 2026-10-27), `billing=api_credit ∧ account=iu|me|me2` → `iu-credit` / `me-credit` / `me2-credit` (the API credit each subscription grants; the inference gateway writes these rows, which used to fall to `unknown`), `billing=iu ∧ iu_key=personal` → `iu-api`, `iu ∧ iu_key=athena-team` → `iu-team-api` (the Athena team key; an iu row with NULL `iu_key` — unknown key — is `unknown`), `billing=openrouter` → `me-api` (the personal pay-per-token API), everything else — including Max rows whose account is not (yet) known — `unknown`. Available as `payer[]` filter on `/usage/{headline,timeseries,breakdown}`, as `groupBy=payer` / `dimension=payer`, and as `costIuSub30d`/`costMeSub30d`/`costIuApi30d`/`costMeApi30d` on the headline. `billing` and `account` filters/dimensions are unchanged. `API_PAYERS` (`iu-api`, `iu-team-api`, `me-api`) is the default set wherever "API spend" is meant (`/usage/movers`); `CREDIT_PAYERS` are the three credit pools, not part of it. The `billing` filter enum (`usage-filters.ts`) lists `api_credit` too; `payer[]` is the finer selector. A new payer or billing value needs the CASE, `PAYERS` and the dashboard's `USAGE_PAYERS` registry updated together. Timeseries buckets are UTC days (pinned in SQL; prod Postgres is `Etc/UTC`). Migration `0024` was reversible from the off-repo pg_dump of its archive table, which `0025` dropped (history in `docs/usage-reconciliation.md`; the table it acted on went in `0032`). Tests: `src/routes/usage.payer.test.ts` (payers and the credit payers over seeded rows), `src/lib/usage-query.test.ts` (DB-free, the CASE text); route tests need the scratch Postgres: `bun test:api src/routes/usage`.

Claude account quota samples (`usage.quota_samples`, key `(account, sampled_at, machine)`) and picker decisions (`usage.account_picks`, key `(ts, lane, machine)`) are written by `usage-tracker` straight into the `usage` schema; Argo only reads them (no ingest endpoints). Picker spec: `dotfiles/docs/claude-accounts.md` §The picker. `picked` is opaque: an account id or `spill`. Reads: `GET /usage/quota` (buckets widen with the window: 15 min ≤72 h, 1 h ≤30 d, 1 d beyond; last sample wins; resets as markers; future-stamped rows ignored), `GET /usage/quota-latest[?account[]]` (the newest unbucketed sample per account, `{accounts:[{account,sampledAt,fiveHourPct,sevenDayPct,sevenDayResetsAt,authOk}]}`, future-stamped rows ignored, empty = `{accounts:[]}`; the usage page's weekly meters and pace tick read it because `/quota` carries no reset instant or `authOk`) and `GET /usage/account-picks/summary` (`groupBy=picked|reason` for the series, `lanes` = per-lane spill rate). Routing views (`src/lib/routing.ts`, pure): `GET /usage/account-picks?hours≤504` lists every decision with its parsed `{s,w}` snapshot; `GET /usage/routing/windows?hours` gives per account and window (5 h / 7 d) the percent used in the last sample before each reset (unused = 100 − that) and, for 5 h, the minutes until the account was picked again, plus a per-account summary. The routes live in `src/routes/usage-quota.ts`, mounted inside `usageRoutes` (no prefix of their own, so the `/usage` auth guard and Eden path are shared). Tests: `src/routes/usage.quota.test.ts`.

## Models (modelpick relay)

`src/routes/models.ts` relays `GET /models/efficiency` to `GET /api/efficiency` of the modelpick server (repo `~/SourceRoot/modelpick`) at `127.0.0.1:${MODELPICK_PORT:-7727}`. The server is loopback-only and read-only, so there is no service token (and Argo's bearer is not forwarded); the bearer guard on Argo's API still applies. The service's status and JSON body pass through; service down or timed out (30 s) → `503 {"error":"models service unavailable"}`. The payload is Artificial Analysis' data joined with the agw route table: the contract is pinned in the dashboard (`features/models/api/types.ts`); keep `source.attribution` wherever it is displayed. Tag `Models`.
