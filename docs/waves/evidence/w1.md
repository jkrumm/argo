# Evidence — Wave 1: argo against basalt-ui 2.0

Measured 2026-10-14 against argo `master` @ `7ced251` (dashboard pinned `basalt-ui` 1.36.0, root
1.41.0) and the **published** `basalt-ui@2.0.0` tarball (`npm pack basalt-ui@2.0.0` into a scratch
dir; nothing below is from memory or from basalt-ui's source tree). Export lists come from the
tarball's `.d.ts` entry points via the TypeScript checker (`getExportsOfModule` per `exports` entry);
argo's import names come from parsing every `import … from 'basalt-ui…'` under `apps/`.

## 1. Surface

`./agent-chat` (→ `./agent`), `./notifications` (→ `./commands`), `./data/table` (→ `./table`),
`./router-tanstack` (→ `.` and `./state`), `./theme-lab` (provider-mounted in dev).

them resolves on 1.41.0, so the 1.36 → 1.41 step is import-safe.

## 3. What the bump actually breaks — measured

Scratch worktree of `7ced251`, `bun add basalt-ui@2.0.0` plus the peers above, `tsc -p tsconfig.app.json`:

| Step                                                                 | tsc errors | In chart files (38 files) | Elsewhere |
| -------------------------------------------------------------------- | ---------- | ------------------------- | --------- |
| install only                                                         | 498        | 305                       | 193       |
| + the three mechanical specifier moves (`agent-chat`, `notifications`, `data/table`) | 402        | 305                       | 97        |

After the moves, **every table file and every chat file but one compiles**. The remaining 97 are
the wiring: `Register` never established (31 × `queryClient` on `never` cascade from `lib/router.ts`),
the deleted root exports above, `paletteOptions.groups` (`Record<string, SeriesMap>` → `SeriesGroup[]`),
`PageBar` `actions.secondary` (2 sites → tuple), one `RangeField` handle in `routes/strength-tracker.tsx`,
and `BasaltShell` requiring `nav`. Charts are the bulk and are not mechanical.

**Lint:** the 2.0 generic preset's newly-`error` rules, run with oxlint 1.87 over
`apps/dashboard/src` today: `react/refs` 10, `react/set-state-in-effect` 4, `react/purity` 2,
`react/globals` 1, `typescript/no-explicit-any` 0, `no-constant-binary-expression` 0.

## 5. Observability seam vs HyperDX

`lib/hyperdx.ts` initialises `@hyperdx/browser` as the first import (patches `fetch`, propagates
`traceparent` to `/api/`). 2.0 replaces `onError`/`BasaltErrorContext` with `BasaltProvider telemetry`
(`BasaltEvent`); V2-SPEC § 7 Open #6 — whether `@hyperdx/browser` registers the global
`@opentelemetry/api` tracer provider — is unresolved and is argo's to answer. The server span
`hermes.stream-lifecycle` (`apps/api/src/routes/hermes.ts:968-1029`) carries `argo.hermes.thread_id`;
`chat.turn` carries `basalt.chat.thread_id`.

## 6. Baseline gaps

`basalt-ui:docs/waves/evidence/w2/argo-baseline-1.36.md` has bundle, screens and Lighthouse only, of a
static build with no API (every screenshot is an empty or error state); charts-perf, chat-profile and
otel failed on argo's DOM. It is not a usable before-picture for chart ports. Wave 2 records a
real-data baseline on 1.41.

## 7. Docs that disagree (verified in the tarball)

- `MIGRATING.md` § 2.0 "Upgrading from 1.x" step 2 says delete your `@mantine/*/styles.layer.css`
  imports because `styles.css` carries them; `styles.css` `@import`s only core, notifications and
  spotlight, and the `basalt-app` skill says to import `@mantine/dates/styles.layer.css` **after** it.
  `@mantine/schedule` (argo's calendar) is mentioned nowhere.
- The font peers are exact `5.2.x` while argo runs `5.3.0`; `bun add` accepted the mismatch silently.
- argo's `package.json` `basalt.chartMissingAriaLabel` configures a guard kind 2.0 deleted
  (`ariaLabel` is a required prop now).
