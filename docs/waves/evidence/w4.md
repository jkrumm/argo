## Lane 2 — view transitions

Init script wraps `document.startViewTransition` and counts calls. Client-side clicks on the sidebar links, nav order
(Hermes, Calendar, Garmin, Strength, Body, WalkingPad, Reading, Astro, Usage, Agents, Warden, M365) then reverse, 12
destinations; `/` is a redirect to Garmin and was not clicked separately (13th route).

- First load: 0 calls (no-preference and reduce).
- Every route change, forward (11) and reverse (11), plus back to Calendar: exactly 1 call each, both motion modes.
- Search-only changes (calendar next-week, Week to Month, history back over a search change): 0 calls.
- History back over a route change: 1 call.
- Latency click to call: 28-365 ms, except Usage Tracking first visit 1152-1756 ms and M365 first visit 756-873 ms (route loader
  waits on production). A fixed 900 ms read window wrongly showed `0` for Usage Tracking on the first pass; with polling it is 1.
- no-preference: 4 `::view-transition-*` pseudo animations per navigation (root and `basalt-main` groups, old/new).
- `prefers-reduced-motion: reduce`: `document.getAnimations()` contained 0 `::view-transition-*` animations across all
  navigations. PASS.

scenario: 5 routes by sidebar click, one search-only change, `GET /api/recovery` forced to 500. Traces are OTLP JSON.

- The first run on `66d9f04` produced 0 `basalt-ui` spans (api 1.9.1 rejected HyperDX's global 1.8.0). After the pin they arrive. PASS.
- `service.name` = `argo-dashboard` on all resources. PASS.
- `route.navigate` x6 (5 route changes, plus calendar to calendar for the search-only change), scope `basalt-ui`, status unset, 23-1577 ms.
  Attributes: `basalt.route.id`, `basalt.route.from`, `url.path`, e.g. `/garmin-health`, `/calendar`, `/garmin-health`. PASS.

  `exception.type` = `Error`, `basalt.error.kind` = `query`. All 7 listed attributes seen across the two span names. PASS.
- Also emitted, not in the brief: `route.error` on `/garmin-health` (`basalt.error.kind` = `route`, `exception.type` = `Error`), which is consistent
  with the forced failure.
- Message/stack: the 500 body marker is absent from all traces and logs (0 files). No `exception.message` or `exception.stacktrace` on any basalt span. PASS.
- Search params: basalt's own attributes carry none (`url.path` is the bare path). FAIL as a whole span: HyperDX stamps `location.href` on
