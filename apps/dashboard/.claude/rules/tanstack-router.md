# TanStack Router — File-Based Routing Conventions

## Adding a page

1. Create `src/routes/<page-name>.tsx`
2. Export `Route` using `createFileRoute('/<page-name>')`
3. Add `validateSearch` with a Zod schema for URL state (filters, pagination, active tab)
4. Add a `loader` that calls `ensureQueryData` for each query the page needs
5. Add the nav link in `__root.tsx`

## Route structure

```ts
import { createFileRoute } from '@tanstack/react-router'
import { z } from 'zod'
import { queryClient } from '../lib/query-client'
import { myQueries } from '../lib/queries/my-resource'

const SearchSchema = z.object({
  window: z.enum(['7d', '30d', '90d', 'all']).default('30d'),
})

export const Route = createFileRoute('/my-page')({
  validateSearch: SearchSchema,
  loader: ({ context: { queryClient } }) => queryClient.ensureQueryData(myQueries.summary()),
  component: MyPage,
})
```

## validateSearch

- Always use a Zod schema — never raw object defaults.
- Default values live in the schema (`.default()`), not in the component.
- Access via `const search = Route.useSearch()`.
- Update via `navigate({ search: (prev) => ({ ...prev, key: value }) })`.

## Loaders

- Use `ensureQueryData` (not `fetchQuery`) so cached data is reused.
- The loader receives `context: { queryClient }` — set this up in `main.tsx` router config.
- Loaders do not return data — components read via `useSuspenseQuery`.

## Route tree

`src/routeTree.gen.ts` is auto-generated by the Vite plugin — never edit it. Regenerated by `tsr generate` (also runs as part of `typecheck`).
